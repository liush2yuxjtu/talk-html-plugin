# 微信草稿操作与验证

## 工具与连接

从当前会话实际工具列表发现 `wechat_*` 能力；命名空间因客户端而异，不能硬编码历史前缀。
App 显示已安装或 Allow all actions 只代表配置，不能证明远端连通。

1. 调用 `wechat_check_auth`，检查返回内容和错误标记。
2. 修改时调用 `wechat_get_draft({media_id})`，确认标题、目标 `news_item[index]` 和实际内容。
3. 工具不存在、连接失败、微信鉴权失败、参数错误分别诊断。连接错误最多做一次有界重试。
4. 工具已暴露但返回 `UNAVAILABLE / Connection failed` 时，不声称未挂载，也不要求无证据的重新登录。
5. 恢复后从最后已验证状态继续。鉴权成功只证明认证；读旧稿成功只证明读取能力。

## 内容门槛与图片

遵守项目保守门槛：标题非空且不超过 32 字符、作者不超过 16 字符、摘要不超过 120 字符，
HTML 小于 20,000 字符且小于 1 MiB；正文非空、无占位符、无 script/style，关键 CSS 内联。
这些是项目本地门槛，不宣称是所有微信账号/API 的最新上限；同时检查当前工具校验结果。

在仓库内运行现有校验器（实际使用时替换文章路径和标题）：

```bash
python3 rednote-gallery/scripts/verify-publishing.py \
  --wechat '<文章目录>/wechat-payload.html' --title '<文章标题>'
```

可用时调用 `wechat_validate_article` 并使用通过校验的内容。
本地校验和此工具都不能证明草稿已在微信保存。
安装环境没有仓库校验脚本时，检查上述同样的内容门槛并调用可用的校验工具，记录真实覆盖范围。

- 正文图片用 `wechat_upload_image({purpose:"content", ...})` 获取微信托管 URL，再写入正文。
- 封面用 `purpose:"thumb"` 获取永久素材 `media_id`，作为 `thumb_media_id`。
- 已有封面未要求修改时保留。上传远程图片时仅使用授权且服务端可访问的来源，
  私有附件先通过授权渠道取得图片字节，再用工具支持的 `image_base64` 上传。
- `rewrite_remote_images` 仅在当前 schema 支持且源图可访问时使用；回读确认重写结果。
- 检查图片是否缺失、顺序是否正确，示意图与真实截图的说明是否保留。

## 创建或更新

| 情况 | 调用 | 后续验证 |
|---|---|---|
| 新文章且没有目标草稿 | `wechat_create_draft` | 使用本次返回的 media_id 回读 |
| 修改已确认草稿 | `wechat_update_draft` | 使用同一 media_id/index 回读 |
| 写入调用超时，结果未知 | 先查平台状态 | 不盲目重复创建或覆盖 |
| 只恢复了鉴权/读取 | 不算写入成功 | 保留旧稿状态 |

参数按当前 schema 构造：`title`、`content`、`author`、`digest`、`content_source_url`、
`thumb_media_id`、评论设置；更新再传 `media_id` 与目标 `index`。
更新接口需要完整文章字段时，以刚读取的目标文章为底稿合并改动，不漏掉未修改字段。
不要把 get_draft 返回的 `url`、`cover_info` 等只读字段直接转发到 update。

写入前保存旧稿的私有快照和预期版本；若平台稿在编辑期间发生变化，先重新合并或解决冲突。
当前修改授权仅覆盖目标文章，不覆盖同组其他文章或已发表历史。
检查工具错误标记和返回业务错误，不能把工具 transport 成功当作微信业务成功。

## 回读比对与预览

写入成功后必须调用 `wechat_get_draft`，检查目标文章：

- 标题和作者/摘要符合预期；
- 本次修改的关键段落存在，应删除的旧段落已消失；
- 正文非空，章节顺序和图片数量符合预期，封面正确；
- 微信可能将 `src` 规范化为 `data-src`、转义字符或调整 HTML；按解码后的语义、结构和图片核对，
  不要求 HTML 字节完全相等，也不只比较正文长度；
- 取本次回读返回的目标 `news_item[index].url`。URL 字符串未变不表示更新失败；
  URL 变了也不表示正文已更新。

有可用浏览器时打开真实预览，检查移动阅读、图像、断行和来源链接。
只能完成 API 回读时，明确“草稿内容已回读验证”，不宣称已检查视觉效果或读者可访问性。
没有返回 URL 时，如实说明；不拼装、不猜测，不把旧 URL 冒充本次交付证据。

## 状态、发表与续接

| 状态 | 所需证据 |
|---|---|
| `wechat-locally-verified` | 本地内容门槛通过 |
| `wechat-draft-saved` | create/update 业务成功，已知目标 media_id/index |
| `wechat-draft-verified` | 保存后 get_draft 返回本次预期内容 |
| `wechat-publish-submitted` | 明确授权后发表请求受理 |
| `wechat-published` | 最终发布状态成功，并取得真实永久文章标识/URL |

只有用户明确授权发表该稿件后，才调用 `wechat_publish`；`confirm_publish:true` 不是授权来源。
若执行发表，继续查询 `wechat_publish_status`，不能把受理当发表成功。

连接或写入失败时保存：原始输入定位、正文版本、未应用修改、目标 media_id/index、预期内容摘要、
最后成功步骤和下一步。恢复或 fork 后先读取此记录，避免让用户反复复述。
不要将账号标识、完整草稿返回、带 tempkey 的预览链接、附件签名 URL、密钥、cookie 或私有原话
写进公共 Git、skill 示例或日志。给用户的真实预览链接与公开的脱敏验收记录分开保存。

验收至少覆盖一个相关边界：例如回读仍是旧段落时保持未验证，或缺少 v2 修改材料时先恢复来源。
测试 skill 本身时使用只读/隔离场景，未经用户要求不创建、覆盖或发表真实公众号文章。
