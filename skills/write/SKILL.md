# /write — 从随口聊到微信公众号文章

把用户真正想表达的观点变成读者能看懂的文章，并交付任务要求的真实平台结果。
使用当前对话和已保存的素材自主推进，普通编辑决策无需逐步确认。

## 1. 接住原话，恢复上下文

- 收集相关聊天、语音转写、截图、原始链接、旧稿以及用户最近的修改意见。
- 去除口头重复，纠正有证据支持的转写错误，保留立场、语气、例子和真实经历。
- 先从上下文提炼读者、核心问题、一句话观点、希望读者获得什么以及输出平台。
- 将原话、作者判断、可核实事实、待核实主张分开。不要把用户的猜想写成事实。
- 续写或 fork 后，先查已关联的 source/version、项目文件或交接记录，再向用户索要缺失内容。
  只知道 media_id 或读到了旧草稿，不代表已经知道 v2 修改要求。
- 仅在核心观点相互冲突、目标草稿无法唯一确定、关键材料找不到或需要新授权时，问一个最小问题。

## 2. 从观点组织文章

- 先定一个读者问题和一条主线，再组织开头、解释、具体例子、适用边界和收尾。
- 默认用简体中文短段落；保留作者口吻，去掉转写噪声、套话和反复总结。
- 只有亲历素材才写成第一人称经历；不要编造对话、数据、引用、人物观点或使用效果。
- 产品更新、人物原话、价格、技术能力等需要查证时，优先读取官方原文与原始视频/帖子。
  保存可追溯来源，把推断标清；未经核实的关键主张不能包装成已确认新闻。
- 用自然叙事串起信息。技术原理难懂时补一个简单例子或准确图解，不把工具日志写进正文。
- 将 source、正文、图片说明和来源保存在本次文章的私有工作目录中，保留版本，便于按反馈修订。

## 3. 按交付目标分流

| 用户要什么 | 执行到哪里 | 交付什么 |
|---|---|---|
| 写一篇文章，尚未指定平台操作 | 完成正文 | 完整文章 |
| 做公众号排版或本地预览 | 生成微信兼容 HTML | 排版稿，并准确说明尚未写入微信 |
| 放进公众号草稿、给微信预览 | 创建/更新并回读目标草稿 | 微信返回的真实草稿 URL |
| 修改已有公众号文章草稿 | 先读取旧稿，应用本次修改，再回读 | 已验证版本的真实草稿 URL |
| 公开发表 | 先准备并验证完整草稿，确认该稿的明确发布授权 | 授权后执行发表并验证最终结果 |

用户已要求写入或更新草稿时，直接执行相应草稿操作；这不构成公开发表授权。
请求“文章”本身不自动授权写入平台。默认不调用 `wechat_publish`。

## 4. 配图与公众号排版

- 仅在帮助读者理解或用户要求时配图。官方截图用于展示真实产品，概念图标注为示意。
- 修改现有图片前先查看原图；找不到原图时恢复原附件，不凭空描述原图内容。
- 精确流程/数据图使用 SVG 或绘图工具，概念插画使用当前可用的图像生成工具。
- 独立 SVG 可作为可编辑源文件保留；微信正文使用经过验证可显示的 PNG/JPEG 等图片。
  不依赖 SVG 动画、JavaScript、iframe 或站外页面来承载核心内容。
- 使用单列排版、内联关键样式和清楚的标题层级。标题、作者、摘要和正文遵守项目保守长度门槛。
- 读取 [微信草稿操作与验证](references/wechat-drafts.md)，上传封面和正文图片，检查微信转换后仍可读。
- 不把 ChatGPT 私有附件地址、临时签名 URL、本地文件路径直接嵌入公众号正文。
- 不承诺站外链接一定可点击；回读并在可用时检查真实预览，必要时保留来源名称与可复制地址。

## 5. 保存、回读、再交付

按参考文件执行 `发现工具 → 鉴权 → 校验/图片上传 → create 或 update → get_draft → 内容比对`。
在本仓库工作时，同时遵守 `.agents/skills/publish-rednote-wechat/SKILL.md` 的领域验证规则。
安装后的插件缺少该项目文件时，按本 skill 自带参考文件完成微信流程；不要依赖不存在的仓库路径。

- 版本记录至少包含 source/version、修改要求、目标草稿的 media_id/index、标题、预期关键段落、
  图片数量、操作结果和回读时间；敏感字段只保存到授权的私有位置。
- 修改同一草稿时复用已确认的 media_id/index，保留其他字段及同组其他文章。
- 只有写入成功且回读内容匹配，才声称新版草稿已验证。
- 预览 URL 可能不随正文更新而改变，也可能过期；用回读内容证明版本，不用 URL 是否变新证明。
- 用户只要预览链接时，优先给该链接和一句准确状态。不要拿本地 HTML、旧稿或发布链接冒充新版草稿。
- 若被阻塞，交付已完成的正文并保存续接信息，指出实际失败阶段；不要反复要求重登或重挂载。

## 调用示例

`/write 把刚才随口聊的观点写成公众号文章，保留我的口吻，放到草稿箱给我看，不发布。`

`/write 按刚才两条修改意见更新已有草稿，保留封面，给我微信里的预览。`

编辑本 skill 或其发布流程后，执行项目要求的 `/verify`，再提交变更供审阅。
